## 1. Требования формы

Кладовщик открывает «Отгрузки», нажимает «Новая отгрузка», заполняет карточку и нажимает «Сохранить». Сервер проверяет поля, записывает документ в статусе «Новая» и выдаёт QR-код вида `SHP-` и 16 шестнадцатеричных символов. На карточке появляется «Отгрузка сохранена». Без входа открывается страница «Вход», а запрос без токена получает HTTP 401 и «Требуется аутентификация».

Создавать отгрузку может кладовщик, старший смены и администратор: старшая роль включает права младшей. Поля со звёздочкой обязательны. Подсказки перевозчика («Собственный транспорт», «Белпочта», «Европочта», «Автолайт Экспресс») список не закрывают.

| Поле | Правило |
| --- | --- |
| Номер заказа | Обязателен. Пробелы по краям снимаются, буквы переводятся в верхний регистр. Длина 3–32. Первый символ — латинская буква или цифра, далее латиница, цифры и дефис. Пусто: «Номер заказа обязателен». Иной вид: «Номер заказа: 3–32 символа, латиница, цифры и дефис». Повтор: HTTP 409, «Отгрузка с таким номером заказа уже существует», «Номер заказа занят». |
| Получатель | Обязателен, 2–200 символов после снятия пробелов. Пусто: «Получатель обязателен». Короче: «Получатель не короче 2 символов». Длиннее: «Получатель не длиннее 200 символов». |
| Адрес доставки | Обязателен, 5–500 символов. Пусто: «Адрес доставки обязателен». Короче: «Адрес доставки не короче 5 символов». Длиннее: «Адрес доставки не длиннее 500 символов». |
| Плановая дата | Обязательна, формат ГГГГ-ММ-ДД, реальный день, не раньше сегодня. Пусто: «Плановая дата обязательна». Нет такого дня: «Такой даты не существует». Раньше сегодня: «Плановая дата отгрузки не может быть в прошлом». В календаре формы минимум — сегодняшний день. |
| Количество мест | Целое от 1 до 1000. На форме по умолчанию 1, минимум 1, максимум 1000, шаг 1. Если поле в запросе нет, сервер ставит 1. Меньше 1: «Количество мест не меньше 1». Больше 1000: «Количество мест не больше 1000». Дробь: «Количество мест – целое число». Не число: «Количество мест должно быть числом». |
| Общий вес, кг | Необязателен. Число от 0 до 50 000 включительно. Пустое поле на карточке — прочерк. Меньше 0: «Вес не может быть отрицательным». Больше 50 000: «Вес не больше 50 000 кг». Лишние знаки после запятой сначала округляются до трёх, затем проверяется граница. У поля формы есть минимум 0 и шаг 0,001, верхней границы у самого поля нет. |
| Перевозчик | Необязателен, не длиннее 100 символов. Длиннее: «Перевозчик не длиннее 100 символов». |
| Комментарий | Необязателен, не длиннее 2000 символов. Длиннее: «Комментарий не длиннее 2000 символов». |

Статус и QR-код клиент не задаёт. Если передать их в запросе, сервер отбрасывает эти поля. Ошибка полей приходит как HTTP 400 и «Ошибка валидации», в подробностях — все найденные сообщения. Успех — HTTP 201.

## 2. Тест-дизайн

### Тест-кейс и атрибуты шаблона

Тест-кейс описывает одну проверку так, чтобы её можно было повторить и сверить с эталоном. ID не даёт смешать проверки. Приоритет High, Medium или Low показывает, что выполнять раньше. Предшествующие условия фиксируют вход и данные, которые уже должны быть. Тестовые данные задают конкретные значения, а не «корректный адрес». Шаги задают порядок. Ожидаемый результат — с чем сравнивать. Фактический результат пишется после выполнения: текст на экране или ответ сервера. Постусловия говорят, что осталось в системе. Статус — Passed, Failed, Blocked или Skipped.

### Эквивалентные классы и границы этой формы

Класс эквивалентности — набор значений, на которых система ведёт себя одинаково. Внутри класса достаточно одного представителя. Границу проверяют отдельно: само крайнее допустимое значение и соседний шаг снаружи. Для этой формы границы такие.

| Поле | Допустимый класс, границы | Недопустимый класс | Кейсы |
| --- | --- | --- | --- |
| Номер заказа | 3–32 символа нужного алфавита; края `A1B` и 32 символа; нижний регистр и пробелы по краям приводятся к виду `LAB2-003` | пусто; `AB`; 33 символа; `-LAB`; `ЗАКАЗ-17`; занятый `LAB2-015` | 001, 003–007, 015, 017, 024, 029 |
| Получатель | 2–200 символов; края `Яя` и 200 букв «Я» | пусто; `Я`; 201 буква «Я» | 001, 004, 005, 008, 020, 024 |
| Адрес | 5–500 символов; края `Минск` и 500 букв «А» | пусто; `Минс`; 501 буква «А» | 001, 004, 005, 009, 021, 024 |
| Плановая дата | существующий день, сегодня или позже; край 20.11.2026; пример 27.11.2026 | пусто; 19.11.2026; 2026-02-31 | 001, 004, 010, 018, 024 |

### Таблица решений

Исход зависит от трёх условий. Роль отдельным условием не стоит: все три роли создают отгрузку. Прочерк значит, что условие уже не влияет.

| Правило | Вход есть | Поля допустимы | Номер свободен | Результат | Кейсы |
| --- | --- | --- | --- | --- | --- |
| R1 | нет | — | — | страница «Вход»; HTTP 401, «Требуется аутентификация» | TC-SHIP-016 |
| R2 | да | нет | — | HTTP 400, «Ошибка валидации», записи нет | TC-SHIP-006…014, 017, 018, 020…025, 029 |
| R3 | да | да | нет | HTTP 409, «Номер заказа занят» | TC-SHIP-015 |
| R4 | да | да | да | HTTP 201, статус «Новая», выдан QR-код | TC-SHIP-001, 002, 004, 005, 019, 027, 028, 031 |

R4 проверен тремя ролями: кладовщик (TC-SHIP-001), администратор (TC-SHIP-028), старший смены (TC-SHIP-031).

### Состояния отгрузки

При создании статус не выбирается. Документ появляется как «Новая». Это видно на успешных карточках. TC-SHIP-019 и TC-SHIP-031 дополнительно показывают, что переданные `shipped` и `cancelled` начальный статус не подменяют. Дальнейшие переходы в этом наборе не выполнялись. В системе они такие:

| Состояние | Куда можно перейти | Редактирование карточки |
| --- | --- | --- |
| Новая | Сборка или Отменена | можно |
| Сборка | Упакована или Отменена | можно |
| Упакована | Отгружена или Отменена | можно |
| Отгружена | Доставлена; время отгрузки фиксируется | нельзя, отмена уже недоступна |
| Доставлена | переходов нет | нельзя |
| Отменена | переходов нет | нельзя |
